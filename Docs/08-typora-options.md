# Typora 옵션 대장

[적용 가이드](07-typora.md) · [문서 앱 공유 ID](11-cross-app-options.md#shared) · [Obsidian 대응표](10-obsidian-options.md)

`[x]`는 CSS 생성, `[ ]`는 미구현이다. 원본은 TOML로 조정 가능하고 고정은 CSS만 생성한다. 실제 앱 검증은 따로 기록한다.

## 공통 원본과 Typora 전용 설정

팔레트·역할·서체는 [공통 원본](../themes/orange-type/lbrx.toml)에서 관리한다. [Typora 설정](../themes/orange-type/editors/typora.toml)의 `[colors]`에는 인용문·링크·각주 번호·집중 모드의 **Typora 전용 역할 연결 예시**가 있다. 주석 그대로 두면 각 옵션의 기본 동작을 따르고, 필요한 줄을 활성화하면 Typora에서만 역할 연결이 바뀐다. 고정 CSS나 아직 지원하지 않는 기능은 설정 예시로 제공하지 않는다.

본문 폭·문단 간격·제목 조판·본문 강조는 Obsidian과 기능 ID를 공유하지만 값은 각 앱의 TOML에서 조정한다. 동일한 기능이라도 앱의 렌더러와 적용 뷰에 따라 결과가 달라질 수 있다.

## 공통 문서 기능의 Typora 적용

|---|---|
| **D01 문서 배경·본문색** | [x] 원본 `background`, `text`. 두 모드에서 본문과 작성 영역 배경을 비교한다. |
| **D02 본문 글꼴 우선순위** | [x] 원본 `typography.prose.families`. EN → KR → JP → 시스템 대체 순서를 보존한다. |
| **D03 본문 크기·줄 높이** | [x] 원본 `typography.prose.size_px`, `line_height`. 한 줄 내부 간격과 문단 사이 간격을 혼동하지 않는다. |
| **D04 코드 글꼴·크기·줄 높이** | [x] 원본 `typography.mono`. 인라인 코드와 코드 블록 모두에 적용한다. |
| **D05 본문 최대 폭·좌우 여백** | [x] [Typora 원본](../themes/orange-type/editors/typora.toml)의 `[layout]`. 좌우 여백 포함 최대 860px, 좌우 각각 16–32px. 좁은 창에서는 컨테이너를 가용 폭 이내로 줄인다. 표·코드의 넘침은 별도다. 실제 앱 확인은 남아 있다. |
| **D06 문단 앞뒤 간격** | [x] `[paragraph].gap_px`로 최상위 연속 문단 사이 12px. 원문, 줄 높이, 제목·목록과의 간격은 유지한다. |
| **D07 문단 정렬·쓰기 방향** | [x] `[paragraph].alignment = "start"`로 최상위 일반 문단을 시작 쪽에 정렬한다. `"justify"`는 양쪽 정렬, 생략하면 앱 기본값을 유지한다. 쓰기 방향·세로쓰기는 강제하지 않으며 실제 앱의 혼합 문장 편집은 미검증이다. |
| **D08 서체 세부 표현** | 확정 — 기본값 유지. 본문 자간·합자·작은 대문자는 덮어쓰지 않고 제목 대소문자도 변환하지 않는다. 코드의 기존 합자 설정은 별개다. 추가 CSS는 생성하지 않는다. |
| **D09 제목색** | [x] 원본 `heading`을 H1–H6에 연결한다. |
| **D10 제목 단계별 조판** | [x] `[headings.h1]`–`[headings.h6]`로 크기 180/150/130/115/105/100%, 굵기 700/700/600/600/600/600, 단계별 위아래 여백을 지정한다. H1 아래에만 `muted` 색의 1px 구분선을 넣으며 제목색은 유지한다. 실제 앱 화면은 미검증이다. |
| **D11 제목 자동 번호** | 확정 — 테마에서 자동 번호를 생성하지 않는다. 원문에 직접 적은 번호는 그대로 표시하며, 목차·개요 동작은 바꾸지 않는다. |
| **D12 링크색·밑줄** | [x] 색은 원본 `link`, 밑줄은 고정. 밑줄을 끄는 옵션은 없다. |
| **D13 키보드 링크 포커스** | [x] 색은 원본 `focus`, 윤곽선 굵기·거리는 고정. 편집기의 집중 모드와 다르다. |
| **D14 인용문** | [x] 색은 원본 `quote`, 시작 방향 테두리·안쪽 여백은 고정. |
| **D15 인라인 코드색** | [x] 원본 `inline_code`. 별도 배경색이나 테두리 옵션은 없다. |
| **D16 일반 텍스트 선택색** | [x] 본문은 `prose_selection_background`, 코드는 `selection_background`, 선택 글자색은 `selection_text`를 사용한다. |
| **D17 본문 강조 표현** | [x] `[emphasis.light]`·`[emphasis.dark]`로 굵게는 오렌지, 기울임은 보색 블루, 취소선은 웜 그레이로 지정하고 각 글자 모양을 유지한다. 형광펜 배경은 라이트 옅은 오렌지·다크 짙은 오렌지 갈색이다. 일반 본문 배경과 형광펜 배경에서 강조 글자 대비 4.5:1을 검사한다. 코드와 드래그 선택색은 별도 역할을 쓰며 실제 앱 화면은 미검증이다. |
| **D18 각주·참조·수평 구분선** | [x] 본문 각주 번호는 기본적으로 청회색인 `function` 역할을 사용하고, `[colors]`에서 Typora에 한해 바꿀 수 있다. `[footnotes]`의 각주 글자는 본문의 90% 크기와 `muted` 색을 쓴다. `[horizontal_rule]`은 Markdown 구분선을 `muted` 색 1px, 위아래 여백 각각 24px로 설정한다. 각주 이동·복귀와 일반 링크는 유지하며, 실제 앱 화면과 내보내기는 미검증이다. |
| **D19 코드 블록 바탕·테두리** | [x] 코드 펜스와 편집 거터는 `code_block_background`, 글자와 테두리는 `text`, `muted`를 사용한다. 모서리·안쪽 여백은 고정이다. |
| **D20 코드 구문색** | [x] 원본 `comment`, `keyword`, `string`, `function`, `number`, `error`. Typora는 `.cm-s-inner`에 연결하지만 Obsidian은 해당 앱의 렌더러에 따로 연결해야 한다. |
| **D21 표** | [x] `[table]` 균형형. 헤더는 `surface` 배경과 굵은 글씨, 셀은 위아래 8px·좌우 12px 여백과 1px 가로선만 적용한다. 화면에서 넓은 표는 표 영역 안에서 가로 스크롤하며, Markdown 열 정렬은 덮어쓰지 않는다. 실제 앱의 표 편집 도구와 내보내기는 미검증이다. |
| **D22 순서·비순서 목록** | [x] `[lists]` 균형형. 단계별 24px 들여쓰기, 연속된 일반 항목에 4px 간격을 적용한다. `[lists.markers]`의 `level_1`, `level_2`, `level_3`에서 비순서 표식을 `disc`(●)·`circle`(○)·`square`(■) 중 하나로 변경한다. 각 단계는 생략하면 기존 ● → ○ → ■를 따르며, `level_3`은 3단계 이상에 적용된다. 순서 목록의 시작 번호와 작업 목록의 체크박스·완료 스타일은 유지한다. 실제 앱 화면은 미검증이다. |
| **D23 작업 목록** | [x] `[task_lists]` 균형형. 미완료는 기본 본문색과 빈 체크박스를 유지한다. 완료 체크박스는 기본 `accent`를 사용하며 `checkbox_color = "warning"`처럼 두 모드에 존재하는 역할 이름으로 바꿀 수 있다. 완료 항목의 직계 문단에만 `muted` 색과 취소선을 적용하며 `strike_completed = false`로 취소선을 생략할 수 있다. 실제 앱 화면은 미검증이다. |
| **D24 이미지·캡션** | [x] `[images]` 균형형. 독립 이미지는 본문 폭을 넘지 않고 확대하지 않는다. `alignment`로 `start`(시작)·`center`(가운데)·`end`(끝)를 선택한다. 생략하면 기존 가운데 정렬과 일반 Markdown 이미지의 앱 기본 규칙을 유지한다. 명시적인 이미지 `figcaption`은 가운데 정렬과 8px 간격·본문의 90% 크기·`muted` 색을 유지한다. 대체 텍스트로 캡션을 만들거나 원본 파일을 변경하지 않는다. 실제 앱 화면은 미검증이다. |
| **D25 수식** | [x] `[math]` 균형형. 독립 수식은 `surface` 배경과 위아래 12px·좌우 16px 안쪽 여백을 쓴다. 새 가로 스크롤 규칙은 화면의 수식 렌더링 영역에만 적용한다. 인라인 수식, 수식 글꼴, 원문은 바꾸지 않는다. 실제 앱 화면과 내보내기는 미검증이다. |
| **D26 알림·콜아웃** | [x] `[alerts]` 균형형. 기본은 `surface` 배경과 NOTE(파랑), TIP(녹색), IMPORTANT(딥 블루), WARNING(황색), CAUTION(붉은색)의 왼쪽 강조선·제목색이다. `[alerts.colors]`에서 바꿀 유형만 지정한다(예: `note = "accent"`). 값은 양쪽 모드의 공통 역할 이름이며, 생략한 유형은 기본색을 유지한다. 기본 아이콘·라벨과 일반 인용문을 유지하며 Obsidian에는 적용하지 않는다. 실제 앱 화면은 미검증이다. |

## Typora 전용

- [x] **T01 테마 패키지** — 고정. `lbrx-light.css`, `lbrx-dark.css`, 적용 안내를 생성한다. 앱에 복사하거나 모드를 자동 전환하지 않는다.
- [x] **T02 집중 모드** — `[colors]`의 `"--blur-text-color" = "muted"` 예시를 활성화하면 Typora가 집중 모드에서 흐리게 표시하는 글자색을 바꾼다. 생략하면 변수를 출력하지 않아 앱 기본값을 유지한다. 모드를 켜거나 활성 영역의 스타일을 직접 변경하지 않으며, 실제 앱 화면은 미검증이다.
- [x] **T03 라이브 편집 기호** — `[colors]`의 `--lbrx-live-edit-marker`, `--lbrx-live-edit-link-text`, `--lbrx-live-edit-link-url`로 편집 중 드러나는 강조·링크 기호, 링크 표시 텍스트, 목적지 URL의 색을 각각 바꿀 수 있다. 각 키를 생략하면 기존 색을 유지한다. 기호의 표시·숨김과 닫힌 일반 링크는 변경하지 않는다. 실제 앱 화면은 미검증이다.
- [x] **T04 코드 편집기 줄 번호·커서 색** — `muted`, `focus`를 매핑한다. 줄 번호 표시 여부는 변경하지 않는다.
- [x] **T05 코드 편집 상태** — `[colors]`의 `--lbrx-code-*` 예시로 CodeMirror 코드 펜스의 선택 배경·글자색, 활성 줄 배경, 짝이 맞는/없는 괄호 색을 각각 조정한다. 생략하면 기존 CSS를 유지하고, 본문과 Markdown 소스 모드는 변경하지 않는다. 활성 줄·괄호는 앱이 해당 표시를 생성할 때만 적용하며, 실제 앱 화면은 미검증이다.
- [x] **T06 Markdown 소스 모드** — `[source_mode]`에서 공통 글꼴 목록(`mono`/`prose`)과 기본 글자 크기(px), `[source_mode.colors]`에서 배경·일반 글자·구문·선택·활성 줄·커서·줄 번호 색을 각각 변경할 수 있다. 생략하면 기존 CSS를 유지하며, 일반 본문과 코드 펜스에는 적용하지 않는다. 구문 분류와 줄 번호 표시 여부는 Typora가 결정한다. 실제 앱 화면은 미검증이다.
- [x] **T07 문서 내부 `[TOC]`** — `[toc]`에서 항목 간격·기본/호버 링크 색·밑줄·표시 깊이(H1–H6)·자동 일련번호, `[toc.indent_px]`에서 단계별 들여쓰기를 지정한다. 표시 깊이와 번호는 목차에만 적용하고 본문 제목 및 사이드바 개요는 바꾸지 않는다. 생략하면 기존 CSS를 유지한다. 실제 앱 화면과 내보내기는 미검증이다.
- [x] **T08 사이드바·파일 목록·개요·파일 트리** — 기본 `[sidebar]`의 `background = "surface"`, `text = "text"`, `muted = "muted"`가 라이트·다크 배경과 탭·목록 글자색을 함께 적용한다. `background`는 Typora의 사이드바 배경·파일 선택·호버·포커스 변수를 연결한다. 파일 목록 선택·호버는 공통 선택 배경/글자색, 활성 탭은 `focus`를 사용한다. `muted`는 요약·폴더·시간·확장자의 중첩 투명도를 제거해 대비를 유지한다. 생략한 항목은 기존 동작을 유지한다. `[sidebar.outline]`은 개요의 단계별 들여쓰기·일련번호, `[sidebar.outline.colors]`와 `[sidebar.file_tree]`는 개요·트리의 상태색을 별도 지정한다. 접힘 상태·파일 순서·표시 여부·본문·`[TOC]`는 변경하지 않는다. 설치본 CSS 선택자와 생성 결과를 검증하며 실제 앱 화면은 별도 확인한다.
- [x] **T09 YAML 머리말·편집 보조 UI** — `[editing_aids.yaml]`의 메타데이터 블록·빈 안내, `[editing_aids.search]`의 문서 내 검색 결과, `[editing_aids.link]`의 펼쳐진 인라인 URL·링크 제목 배경을 조정한다. 두 기본 스타일은 YAML `background = "surface"`, `text = "text"`, `placeholder = "muted"`를 활성화한다. YAML 내부 CodeMirror와 거터의 기본 회색 배경도 함께 덮어 다크 속성의 밝은 글자가 회색에 묻히지 않게 한다. 설치본에서 확인한 인라인 편집 영역을 대상으로 하며 별도 링크 팝업은 지원하지 않는다. 설정을 생략하면 기존 스타일을 유지한다. 실제 앱 화면은 미검증이다.
- [x] **T10 Mermaid 배색·정렬** — `[diagrams.mermaid]`에서 모드별 Mermaid 배색 프리셋과 미리보기 정렬을 선택한다. 라이트 `neutral`/다크 `dark`는 비활성 예시다. 배색은 렌더러 기본값만 지정하며 문서 내부 Mermaid 설정을 고치거나 SVG의 노드·연결선·레이블 색을 CSS로 강제하지 않는다.
- [x] **T11 Mermaid 도식별 표현** — 같은 표에서 시퀀스 자동 번호, 흐름도 연결선 곡선, 간트 왼쪽 여백을 각각 변경한다. 생략 시 번호를 포함한 기존 동작을 유지한다.
- [x] **T12 기타 다이어그램** — `[diagrams.sequence]`에서 `simple`/`hand`와 미리보기 정렬을, `[diagrams.flow]`에서 미리보기 정렬을 변경한다. `flow` 개별 도형·연결선 스타일은 문서 구문에 남긴다. T10–T12의 실제 앱 화면과 내보내기는 미검증이다.
- [x] **T13 다크 환경설정 왼쪽 메뉴 대비** — 메뉴 배경·글자 및 선택·마우스 오버·포커스 색을 생성한다. 문서 탐색 사이드바(T08)와는 별개이며, 실제 앱 화면 검증은 아직 남아 있다.
- [x] **T14 라이트 환경설정 오른쪽 내용 대비** — 오른쪽 패널에 밝은 배경과 어두운 본문·안내문 색을 짝지어 적용하고, 브라우저 기본 입력 컨트롤에는 라이트 색상 체계를 요청한다. 왼쪽 메뉴에는 적용하지 않는다. 실제 앱 화면 검증은 아직 남아 있다.

## 내보내기와 앱 소유 설정

| ID | 옵션 | LBRX 구현 상태·경계 |
|---|---|---|
| X01 | 인쇄·PDF용 밝은 종이색, 텍스트·링크색 | `[print]`에서 선택적으로 생성. 라이트 색 역할을 사용하고 `@media print`로 편집 화면과 분리한다. |
| X02 | 제목 고립 방지, 그림과 캡션 묶기 | `[print]`에서 각각 선택. 표·코드의 분할은 제한하지 않는다. 실제 여러 페이지 Typora PDF는 아직 미검증이다. |
| X03 | HTML 내보내기 테마·개요, 이미지 내보내기 폭·글꼴 크기 | [적용 안내](07-typora.md#내보내기)에서 CSS와 Typora 프로필의 역할을 구분한다. |
| X04 | PDF 용지 크기·머리말·꼬리말·메타데이터 | [적용 안내](07-typora.md#내보내기)에 따라 앱 설정 또는 문서 YAML에서 관리한다. 생성기는 수정하지 않는다. |
| X05 | EPUB CSS·표지, DOCX 참조 문서, LaTeX/Pandoc 템플릿 | 별도 배포 형식. 현재 Typora CSS의 지원 대상으로 계산하지 않는다. |
| X06 | 집중·타자기 모드 활성화, 다이어그램 활성화, 단축키, 이미지 저장·업로드 | 앱 동작. 테마가 자동으로 변경하지 않는다. |
