# Obsidian에 LBRX 적용

저장소 루트에서 `cargo run --locked -- build --app obsidian`을 실행한다. 본문, 앱 UI, 인쇄 옵션은 `themes/lavender-type/editors/obsidian.toml`에서 관리한다. 기능별 검증 기록은 저장소의 `Docs/10-obsidian-options.md`를 참고한다.

## 설치·복구

Typora는 모드별 CSS 두 개를 선택하지만, Obsidian에는 `LBRX` 테마 하나를 설치한다. 한 `theme.css` 안에서 `.theme-light`와 `.theme-dark`를 분리하고, 밝기 모드 선택은 앱에 맡긴다.

| 산출물 | 역할 |
|---|---|
| `dist\lavender-type\lbrx\obsidian\LBRX\manifest.json` | 이름 `LBRX`, 생성기 버전, 제작자, 최소 앱 버전. `1.10.6`은 공식 샘플 manifest의 기준이며 실측한 최소 버전은 아니다. |
| `dist\lavender-type\lbrx\obsidian\LBRX\theme.css` | 공통 토큰을 Obsidian의 색·서체 변수에 매핑한다. 스니펫이나 커뮤니티 플러그인 설치를 전제로 하지 않는다. |

1. **시험용 보관함**에서 먼저 확인한다. 기본 설정 폴더를 쓰는 경우 `<보관함>\.obsidian\themes\LBRX\`에 두 파일이 바로 들어가도록 `LBRX` 폴더를 복사한다. 설정 폴더 이름을 바꿨다면 그 위치를 사용한다.
2. **설정 → 테마/외형(Appearance) → 테마(Themes)**에서 `LBRX`를 선택한다. 목록에 없으면 `LBRX\LBRX`로 이중 복사하지 않았는지, 폴더명과 manifest 이름이 일치하는지 확인하고 앱을 다시 연다.
3. 같은 보관함에서 기본 색상 모드를 라이트와 다크로 바꾼다. 업데이트할 때는 LBRX 패키지 파일만 교체한다. 원복은 기존 테마 또는 기본 테마를 다시 선택하면 된다. 보관함의 설정 JSON, 노트, 스니펫은 덮어쓰지 않는다.

**강조 색상(Accent Color):** 외형에서 강조색을 기본값으로 두면 오렌지 라이트 `#A84B16`, 다크 `#FFC695`가 모드에 따라 자동 적용된다. 이전에 HEX를 직접 입력했다면 강조색의 **기본값 복원**을 눌러 자동 전환을 사용한다. 직접 선택한 색이 있으면 Obsidian이 우선 적용한다. 링크색은 별도 `link` 역할을 따른다.

## 테마 설정

| 공통 원본 | Obsidian에서 의도하는 결과 |
|---|---|
| `background`, `surface`, `text`, `muted` | `--background-primary`, `--background-secondary`, `--text-normal`, `--text-muted`에 대응한다. 본문 외에 같은 변수를 쓰는 사이드바·설정 창의 실제 배경과 글자 조합도 검사한다. |
| `link`, `focus`, 선택색 | 내부·외부·미생성 링크와 키보드 포커스는 의미를 구분한다. DOM 텍스트 선택과 편집기가 그리는 선택 영역을 각각 확인한다. |
| `accent` | 모드별 RGB를 Obsidian 기본 강조색의 HSL 입력(`--accent-h`, `--accent-s`, `--accent-l`)으로 변환한다. 버튼·토글의 파생 상태색은 앱이 계산한다. |
| `typography.prose`, `typography.mono` | 본문은 LINE Seed EN → KR → JP → `sans-serif`, 코드는 D2Coding ligature → `monospace`. 글자 크기는 앱 설정을 유지한다. UI 아이콘과 수식 글꼴은 대상이 아니다. |

**D03 본문 줄 높이:** 저장소의 `themes/lavender-type/editors/obsidian.toml`에서 `[prose].use_shared_line_height = true`이면 읽기 뷰의 문단과 라이브 프리뷰의 일반 본문 줄에 공통 `typography.prose.line_height`(현재 `1.65`배)를 적용한다. `false`로 바꾸거나 생략하면 앱 기본값을 사용한다. 제목·코드 블록·소스 모드·앱 UI에는 별도 줄 높이를 지정하지 않는다. 변경 후 `cargo run --locked -- build --app obsidian`으로 다시 생성한다.

`obsidian.toml`의 주석 처리된 변경 예시는 활성 설정을 **교체**할 때 사용한다. 같은 키의 활성 설정과 예시를 동시에 켜지 않는다.

**D04 코드 블록 줄 높이:** `[code].use_shared_line_height = true`이면 읽기 뷰와 라이브 프리뷰의 여러 줄 코드 블록에 공통 `typography.mono.line_height`(현재 `1.45`배)를 적용한다. `false`로 바꾸거나 생략하면 앱 기본값을 사용한다. 인라인 코드, 코드 글자 크기, 소스 모드는 덮어쓰지 않는다.

**D05 본문 폭·좌우 여백:** `[layout]`은 읽기 뷰와 라이브 프리뷰에 좌우 각각 `16–32px`의 여백을 적용하며, 위아래 여백은 바꾸지 않는다. Obsidian에서 **읽기 편한 줄 길이(Readable line length)**를 켜면 여백을 포함한 최대 폭을 `860px`로 제한한다. 끄면 폭을 제한하지 않는다. 앱의 폭과 여백을 모두 되돌리려면 `[layout]`과 그 아래 활성 키를 주석 처리하거나 제거한다.

**D06 문단 간격:** `[paragraph].gap_px = 12`는 읽기 뷰에서 연속된 최상위 일반 문단 사이에만 `12px`를 적용한다. 라이브 프리뷰의 빈 줄, 본문 줄 높이, 제목·목록·표·코드 블록의 간격은 건드리지 않는다. `gap_px`를 생략하면 앱 기본 간격을 사용한다.

**D07 문단 정렬:** `[paragraph].alignment = "start"`는 읽기 뷰의 최상위 일반 문단을 글이 시작되는 쪽(LTR은 왼쪽, RTL은 오른쪽)에 맞춘다. `"justify"`는 양쪽 정렬이며, 키를 생략하면 앱 기본 정렬을 사용한다. 쓰기 방향·세로쓰기는 강제하지 않고 라이브 프리뷰도 바꾸지 않는다.

**D08 서체 세부 표현:** 기본값은 Obsidian에 맡긴다. 변경하려면 `[prose_detail]` 제목과 원하는 키의 주석을 푼다. `letter_spacing_em`(자간), `common_ligatures`(일반 합자), `small_caps`(작은 대문자), `text_transform`(대소문자 표시)을 독립적으로 지정할 수 있다. 읽기 뷰의 최상위 일반 문단에만 적용하며, 인라인 코드가 있는 문단도 제외한다. 노트 원문은 바꾸지 않는다.

**D09 제목색:** Markdown H1–H6는 읽기 뷰와 라이브 프리뷰에서 공통 `heading` 역할색을 사용한다. `[colors]`에서 `--h1-color`부터 `--h6-color`까지 단계별로 다른 역할을 지정할 수 있다. 노트 이름으로 표시되는 인라인 제목은 별도 `--inline-title-color`를 설정하지 않으면 Obsidian 기본색을 유지한다.

**D10 제목 조판:** `[headings.h1]`부터 `[headings.h6]`까지 본문 대비 크기와 굵기를 설정한다. 기본 크기는 `180/150/130/115/105/100%`, 굵기는 `700/700/600/600/600/600`이다. 읽기 뷰의 최상위 제목에는 단계별 위아래 여백을 적용하며, H1 아래에만 보조 글자색의 1px 구분선을 추가한다. 라이브 프리뷰에서는 크기·굵기만 바뀐다. 제목색·인라인 제목 조판·소스 모드는 변경하지 않는다. 앱 조판으로 돌아가려면 `headings` 하위 섹션 전체를 주석 처리하거나 제거한다.

읽기 뷰는 렌더링된 문서를, 라이브 프리뷰는 커서 위치에 따라 Markdown 기호를 보여주는 편집기를 사용한다. **같은 옵션 ID는 같은 디자인 의도이지 같은 CSS 선택자를 뜻하지 않는다.** 먼저 공식 CSS 변수를 쓰고, 부족한 부분만 뷰에 한정한다. Typora의 `#write`나 코드 펜스 선택자를 복사하지 않는다. 소스 모드, 모바일, PDF는 별도 검증 대상이다.

**D11 제목 자동 번호:** 테마는 제목에 자동 번호를 추가하지 않는다. Markdown에 직접 적은 번호는 그대로 표시하며, 읽기 뷰·라이브 프리뷰·개요에 별도 번호를 넣지 않는다.

**D12 링크색·밑줄:** 내부·외부 링크는 공통 `link` 색을 사용하며, 읽기 뷰와 라이브 프리뷰에서 기본적으로 마우스 오버 여부와 관계없이 밑줄을 표시한다. `[links]`의 키로 밑줄을 개별 조정할 수 있고, `[colors]`에서 일반·마우스 오버 색을 지정할 수 있다. 마우스 오버 색을 생략하면 앱 기본값을 사용한다. D12는 미생성 링크의 색과 밑줄을 별도로 재정의하지 않는다.

**D13 키보드 링크 포커스:** `[links].keyboard_focus_outline = true`이면 읽기 뷰에서 키보드 포커스를 받은 내부·외부 링크에 공통 `focus` 색으로 2px 윤곽선과 2px 간격을 적용한다. `false` 또는 생략 시 앱 기본 표시를 유지한다. 마우스 오버, 라이브 프리뷰, Tab 이동 순서는 바꾸지 않는다.

**D14 인용문:** 읽기 뷰에서 일반·중첩 인용문의 글자와 시작 방향 3px 실선에 공통 `quote` 색을 적용하고, 시작 방향 안쪽 여백을 `0.9em`으로 설정한다. `[blockquote]`에서 색 역할·두께·여백을 개별 변경할 수 있고, 키를 생략하면 해당 항목의 앱 기본값을 유지한다. 라이브 프리뷰·소스 모드와 콜아웃에는 인용문 스타일을 적용하지 않는다. 링크와 인라인 코드의 고유 스타일, 인용문의 배경과 글자 모양은 별도로 바꾸지 않는다.

**D15 인라인 코드색:** 읽기 뷰와 라이브 프리뷰의 인라인 코드에 공통 `inline_code` 색을 사용한다. 링크·표 셀 안의 인라인 코드도 포함하며, 배경·테두리·코드 블록·소스 모드는 변경하지 않는다. `[colors]`의 `"--lbrx-inline-code-color"`로 색 역할을 바꾸거나 키를 생략해 기존 표시를 유지할 수 있다. 설정한 색은 각 모드의 코드 배경과 최소 4.5:1 대비를 충족해야 한다.

**D17 본문 강조:** `[emphasis.light]`·`[emphasis.dark]`에서 읽기 뷰와 라이브 프리뷰의 굵게·기울임·취소선 글자색과 기본 형광펜(`==텍스트==`) 배경을 지정한다. 읽기 뷰에서는 중첩된 안쪽 강조의 글자색이 나타나고, 라이브 프리뷰에서는 한 토큰에 여러 강조가 겹치면 취소선 → 기울임 → 굵게 순으로 색을 우선한다. 글자 모양, 코드, 편집 기호, 명시적으로 색을 지정한 형광펜, 드래그 선택색은 바꾸지 않는다. 본문 배경 및 형광펜 배경에서 강조 글자 대비를 최소 4.5:1로 검사한다. 두 표를 모두 생략하면 D17을 적용하지 않는다.

**D18 각주·참조·수평 구분선:** 읽기 뷰의 각주 참조 번호는 공통 `function` 역할색을 사용하며, `[colors]`의 `"--lbrx-footnote-reference"`로 바꿀 수 있다. `[footnotes]`의 각주 본문은 기본 90% 크기와 보조 텍스트색을 쓴다. `[horizontal_rule]`의 Markdown 수평선은 보조 텍스트색 1px에 위아래 여백 각각 24px를 적용한다. 각주 영역의 자동 구분선, 이동·복귀 동작, 라이브 프리뷰와 소스 모드는 변경하지 않는다. 두 표는 각각 생략해서 기존 표시를 유지할 수 있다.

**D19 코드 블록 바탕·테두리:** 읽기 뷰와 라이브 프리뷰의 코드 블록은 기존 공통 `code_block_background` 바탕색을 유지한다. 읽기 뷰에서는 `[code].reading_border_width_px`로 보조 텍스트색 테두리(기본 `1px`)를 지정하고, `reading_horizontal_scroll = true`로 긴 줄을 줄바꿈하지 않고 가로 스크롤한다. 두 키를 생략하면 기존 동작을 유지한다. 인라인 코드, 라이브 프리뷰의 줄 배치, 편집 커서는 변경하지 않는다.

**D20 코드 구문색:** 숫자·오류는 Obsidian이 해당 토큰을 식별한 코드 블록에서만 표시한다. 읽기 뷰 등 렌더링된 코드에는 언어별 설정이 우선하고, 라이브 프리뷰에서 편집 중인 코드 줄에는 공통색을 사용한다. [지원 범위와 설정 예시](24-obsidian-language-highlighting.md)를 참고한다.

**D21 Markdown 표:** 읽기 뷰 표는 `surface` 배경과 굵은 헤더를 사용한다. 셀은 위아래 8px·좌우 12px 여백과 보조 텍스트색 1px 가로선만 적용한다. 화면에서 넓은 표는 표 영역 안에서 가로 스크롤하며, Markdown 열 정렬, 라이브 프리뷰 셀 선택, Bases 표는 바꾸지 않는다. `[table]`에서 여백·선 두께를 바꾸거나 섹션을 생략해 기존 스타일을 유지할 수 있다.

**D22 순서·비순서 목록:** 읽기 뷰의 일반 목록은 단계별 24px 들여쓰기와 연속된 일반 항목 사이 4px 추가 간격을 사용한다. 비순서 글머리표는 ● → ○ → ■(3단계 이상)이며 `[lists.markers]`에서 바꿀 수 있다. 이 하위 섹션만 생략하면 여백은 유지하면서 Obsidian 글머리표를 사용한다. 순서 목록 번호, 작업 목록, 목록 접기 동작, 라이브 프리뷰의 들여쓰기 가이드는 변경하지 않는다.

**D23 작업 목록:** 읽기 뷰의 완료 체크박스는 기본 `accent` 색을 사용하고, 완료 본문에는 보조 텍스트색과 취소선을 적용한다. 본문이 별도 문단 없이 하위 목록과 같은 항목 안에 있으면 취소선이 하위 항목까지 번지지 않도록 본문에 색만 적용한다. `[task_lists]`에서 체크박스 색 역할을 변경하거나 취소선을 끌 수 있다. 미완료 체크박스, 클릭 동작, 라이브 프리뷰는 변경하지 않는다.

**D24 이미지·캡션:** 읽기 뷰에서 단독 이미지와 이미지 임베드를 기본 가운데에 정렬한다. 이미지나 임베드에 지정한 폭을 강제로 늘리지 않고, 공간이 부족하면 비율을 유지하며 본문 영역에 맞춰 줄인다. 명시적인 이미지 `figcaption`만 가운데 정렬하고 8px 간격·90% 크기·보조 텍스트색을 적용한다. 대체 텍스트에서 캡션을 생성하지 않는다. `[images]`에서 정렬과 캡션 간격·크기를 바꾸거나 섹션을 생략할 수 있다. CSS는 텍스트 노드를 구분하지 못하므로, 읽기 뷰 문단에서 이미지가 유일한 HTML 요소라면 같은 문단에 일반 텍스트가 있어도 이미지가 별도 줄에 표시될 수 있다. 라이브 프리뷰에는 적용하지 않는다.

**D25 수식:** 읽기 뷰의 블록 수식(`$$…$$`)에 공통 `surface` 배경과 위아래 12px·좌우 16px 안쪽 여백을 적용한다. 긴 수식은 화면에서만 수식 렌더링 영역 안에서 가로 스크롤한다. 인라인 수식, 수학 글꼴, 원문, 라이브 프리뷰는 변경하지 않는다. `[math]`에서 여백과 배경을 조정하거나 섹션을 생략해 기존 스타일을 유지할 수 있다.

**D26 콜아웃:** 읽기 뷰와 라이브 프리뷰에서 NOTE(파랑), TIP·HINT(녹색), IMPORTANT(딥 블루), WARNING·ATTENTION(황색), CAUTION(붉은색)에 `surface` 배경과 3px 시작 방향 강조선을 적용한다. 제목과 유형 아이콘은 강조선과 같은 색을 쓴다. `[callouts.colors]`에서 색 역할을 바꾸고, `[callouts].shaded_background = false`로 앱의 배경을 유지할 수 있다. `surface` 배경을 쓸 때 제목색 대비를 최소 4.5:1로 검사한다. 지정하지 않은 유형, 아이콘 모양, 일반 인용문, 중첩과 접기 동작은 변경하지 않는다.

### 앱 UI

**O02 라이브 프리뷰 편집 상태:** `[live_preview]`의 `highlight_active_line`은 편집기에 포커스가 있을 때 활성 줄에 은은한 `surface` 배경을 겹쳐 표시하고, `use_focus_caret`는 텍스트 입력 커서에 공통 `focus` 색을 적용한다. 두 옵션은 각각 끌 수 있다. 커서 모양, Markdown 기호의 숨김·표시, 접기, 소스 모드는 변경하지 않는다.

**O03 소스 모드:** `[source_mode].mute_markdown_markers`는 Obsidian이 Markdown 서식 기호로 식별한 요소만 보조 텍스트색으로 표시한다. 코드 블록과 YAML 속성 영역은 제외한다. 본문·코드 내용의 색, 들여쓰기, 선택색, 커서, 읽기 뷰와 라이브 프리뷰는 변경하지 않는다. `false`로 바꾸거나 키를 생략하면 기존 기호색을 유지한다.

**O04 내부 링크와 임베드:** 읽기 뷰와 라이브 프리뷰의 미생성 내부 링크는 보조 텍스트색과 점선 밑줄로 구분한다. `![[노트]]` 임베드에는 테마 강조색의 시작 방향 2px 실선을 적용하며, 중첩된 노트 임베드에도 같은 규칙을 적용한다. `[internal_links]`에서 두 옵션을 각각 끌 수 있다. 정상 링크의 별칭·제목·블록 참조, 탐색 동작, 이미지·PDF 임베드와 소스 모드는 변경하지 않는다.

**O05 태그·속성:** 읽기 뷰와 라이브 프리뷰의 본문 태그에는 `surface` 배경과 `accent` 글자색을 적용한다. 노트 속성 이름에는 보조 텍스트색, 편집 포커스에는 공통 `focus` 색의 2px 테두리를 적용한다. 속성 값과 태그 칩, YAML 원문, 속성 입력 동작, 사이드바는 변경하지 않는다. `[tags_and_properties]`에서 두 옵션을 각각 끌 수 있다.

**O06 탐색 사이드바:** 파일 탐색기·개요·백링크 패널의 탐색 행에 호버 배경과 현재·선택 상태의 강조 배경을 적용한다. 현재·선택 강조는 앱이 해당 상태를 표시하는 행에만 적용하며, 키보드 포커스 윤곽선도 기존에 포커스할 수 있는 행에만 표시한다. `[navigation_sidebar]`에서 패널별로 끌 수 있다. 정렬·접기·들여쓰기와 본문 속 백링크는 변경하지 않는다.

**O07 작업 공간:** 활성 탭을 `surface` 배경, 굵은 제목, `accent` 색의 2px 아래 표시선으로 구분한다. 리본과 상태 표시줄에는 `surface` 배경을, 분할 경계에는 보조색을 섞은 은은한 구분선을 사용한다. `[workspace]`에서 네 항목을 각각 끌 수 있다. 탭 이동·닫기, 리본 버튼 동작과 패널 크기는 변경하지 않는다.

**O08 설정·명령 팔레트·메뉴:** 데스크톱 설정 창의 왼쪽 메뉴에는 `surface`, 오른쪽 내용에는 `background`를 사용한다. 설정의 활성 탭, 팔레트의 선택 결과, 메뉴의 선택 항목은 강조색을 섞은 배경과 2px 아래 표시선으로 구분한다. 실제 비활성 항목에는 보조 텍스트색을, 기존 키보드 포커스 대상에는 `focus` 색의 2px 윤곽선을 적용한다. 세 범위는 `[dialogs]`에서 각각 끌 수 있다. 명령 팔레트와 같은 구조를 쓰는 다른 선택 창(예: 빠른 전환) 및 Obsidian 공용 메뉴 API를 쓰는 플러그인도 같은 스타일을 사용한다. 별도 구조의 팝업, 모바일, 단축키와 Tab 순서는 변경하지 않는다.

**O09 검색:** 노트 안의 일치에 옅은 `accent` 배경을 적용한다. 읽기 뷰의 현재 일치는 진한 배경과 2px 아래 표시선으로 구분한다. 라이브 프리뷰·소스 모드는 Obsidian이 다음 일치와 모든 일치에 같은 표시를 사용하므로, 앱이 표시한 일치에 동일한 배경을 적용한다. 보관함 검색은 결과에서 일치한 글자만 강조한다. 드래그 선택, 결과 행, 정렬·단축키와 노트에 임베드된 검색은 변경하지 않는다. `[search]`에서 노트 내 검색과 보관함 검색을 각각 끌 수 있다.

**O10 그래프:** 전체·로컬 그래프에 공통 팔레트를 적용한다. 일반 노드는 `muted`, 연결선은 같은 색을 더 옅게 사용하며 레이블은 `text`로 표시한다. 현재 노트와 호버 강조에는 `accent`, 태그·첨부파일·미생성 링크에는 각각 `keyword`·`warning`·`function`을 사용한다. Obsidian이 두 그래프의 색을 같은 위치에서 읽으므로 `[graph].use_theme_palette`로 함께 켜거나 끈다. 사용자 색상 그룹의 우선순위와 물리·필터·확대 동작은 앱의 기존 동작을 유지한다.

**O11 캔버스:** 기본색 카드는 `surface` 배경을 사용하며, 기본색 카드·그룹의 테두리와 연결선은 `muted`로 표시한다. 선택·포커스 카드와 그룹에는 기존 테두리를 보존한 채 `focus` 색의 2px 바깥 윤곽선을 추가한다. 선택 영역과 포커스된 기본색 연결선에도 `focus`를 적용하며, 지정색 연결선은 앱의 기존 강조를 유지한다. 색상 프리셋·직접 지정색과 배치·크기·드래그는 변경하지 않는다. `[canvas]`에서 기본색과 선택 표시를 각각 끌 수 있다.

**O12 Bases:** 표의 열 제목은 `surface` 배경에 굵은 기본 글자색으로 표시한다. 앱이 표시하는 셀·행의 선택 범위에 `accent` 배경을 적용하며, 선택 가능한 범위나 포커스·편집 동작은 바꾸지 않는다. 카드에는 크기를 바꾸지 않는 1px 바깥 경계선을 적용하고 마우스를 올리면 더 진하게 표시한다. 독립 Bases와 노트에 삽입한 Bases에 적용되며, Markdown 표(D21), 정렬·필터, 다른 Bases 뷰는 변경하지 않는다. `[bases]`에서 표와 카드를 각각 끌 수 있다.

**O13 Mermaid:** 읽기 뷰와 라이브 프리뷰의 기본 라벨은 `text`, 도형 배경은 `surface`, 선과 경계는 `muted`를 사용한다. 앱이 제공하는 기본 색상 변수만 설정하므로 문서에서 직접 지정한 색과 다이어그램 종류별 배색은 강제로 덮어쓰지 않는다. 해당 변수를 지원하지 않는 렌더러는 기존 배색을 유지한다. 화면에서 블록 폭을 넘는 경우 블록 내부에서 가로 스크롤할 수 있다. 자동 맞춤·확대, 소스 모드와 인쇄의 넘침 처리는 변경하지 않는다. `[mermaid]`에서 배색과 스크롤을 각각 끌 수 있다.

**O14 앱 아이콘:** 데스크톱 리본과 노트 상단 버튼에서 기본 `muted`, 호버 `text`, 활성 `accent`, 키보드 포커스 `focus`를 사용한다. 북마크와 비활성 상태의 구분을 유지하며, 기본 설정은 앱의 SVG 크기·선 굵기와 버튼 여백을 바꾸지 않는다. `[icons]`에서 두 범위를 각각 끄거나 SVG 크기와 굵기 예시를 활성화할 수 있다. 모바일, 사이드바 트리, OS 앱 아이콘과 아이콘 폰트는 변경하지 않는다.

**O15 모바일:** 터치 도구막대와 좌우 서랍에 `surface` 배경과 기본 글자색을 적용한다. 떠 있는 도구막대의 바깥은 투명하게 유지한다. 휴대폰의 읽기 뷰·라이브 프리뷰에서 기존 본문 좌우 여백을 각 12px까지 줄이며, 기기 안전 영역이 더 크면 그 값을 우선한다. 가상 키보드 높이와 스크롤, 태블릿의 본문 여백, 데스크톱, 소스 모드와 인쇄는 변경하지 않는다. `[mobile]`에서 도구막대·서랍을 각각 끄거나 여백 상한을 변경·생략할 수 있다.

### 인쇄·PDF

**OX01 인쇄·PDF:** Obsidian의 인쇄 문서에만 긴 코드 및 Markdown 표 셀의 줄바꿈을 적용한다. 코드의 공백과 들여쓰기를 유지하고, 여러 페이지에 걸친 표는 인쇄 엔진이 열 제목을 반복할 수 있게 한다. 앱의 PDF 라이트 모드, 용지·여백 설정과 화면 스타일은 변경하지 않는다. `[print]`에서 코드와 표 처리를 각각 끌 수 있다.

## 첫 적용 확인 순서

1. CSS 스니펫과 커뮤니티 플러그인을 끈 시험용 보관함에서 기존 테마·모드·글꼴 설정을 기록한다. 노트 하나에 `Hello, 한글, 日本語`, 제목, `[[기존 노트]]`, `[[없는 노트]]`, 외부 링크, 인용, 선택 가능한 텍스트, 코드 블록, 긴 표, 중첩 작업 목록, 접이식 콜아웃을 넣는다.
2. 같은 노트를 **읽기 뷰 / 라이브 프리뷰 × 라이트 / 다크** 네 조합으로 비교한다. 라이브 프리뷰에서는 커서를 요소 안팎에 놓고 링크 편집, 표 셀 이동, 체크박스 전환이 그대로 되는지도 본다.
3. 기본 본문 대비 7:1, 읽어야 하는 보조 글자와 선택 글자 4.5:1, 포커스와 인접 배경 3:1을 기준으로 검사한다. 사용자 글꼴을 지정한 경우와 스니펫을 다시 켠 경우는 기본 테마 결과와 별도로 기록한다.
4. O08은 라이트·다크에서 설정 창 좌우의 기본·보조 글자 대비를 각각 확인한다. Tab으로 설정 입력/버튼 포커스를 확인하고, 명령 팔레트에서 검색 결과가 없을 때도 입력과 포커스가 보이는지, 방향키로 선택을 옮길 때 강조 표시가 따라가는지 본다. 파일 메뉴에서는 선택·비활성·경고 항목이 구분되고 Enter/Esc 동작이 바뀌지 않는지 확인한다.
5. O09는 같은 단어가 여러 번 나오는 노트에서 읽기 뷰의 현재 일치가 다음·이전 이동을 따라가는지 확인한다. 라이브 프리뷰·소스 모드에서도 검색 일치와 드래그 선택을 비교한다. 보관함 검색에서는 일치 글자만 강조되고 노트 내 임베드 검색과 백링크는 바뀌지 않는지 확인한다.
6. O10은 라이트·다크에서 전체 그래프와 로컬 그래프를 각각 열고 일반·현재·호버 노드, 연결선과 레이블을 확인한다. 태그·첨부파일·미생성 링크와 사용자 색상 그룹을 표시해 색과 기존 우선순위를 확인한다. 확대에 따른 연결선·레이블 변화도 비교한다.
7. O11은 라이트·다크에서 기본색·프리셋·직접 지정색을 사용한 카드·그룹·연결선을 비교한다. 단일·다중 선택과 해제, 연결선 포커스, 드래그와 크기 조절을 확인한다.
8. O12는 라이트·다크에서 독립·삽입 Bases의 열 제목, 셀 범위 선택과 편집, 카드 경계와 호버를 확인한다. 같은 노트의 Markdown 표와 Bases의 다른 뷰에는 변화가 없어야 한다.
9. O13은 라이트·다크의 읽기 뷰와 라이브 프리뷰에서 기본 플로차트·시퀀스의 라벨, 도형과 선을 확인한다. 문서에서 색을 지정한 노드의 색이 유지되는지와 폭이 넓은 다이어그램이 블록 안에서만 스크롤되는지 확인한다.
10. O14는 라이트·다크에서 리본과 노트 상단 버튼의 기본·호버·활성·키보드 포커스 표시를 비교한다. 북마크와 비활성 상태가 여전히 구분되고 기본 설정이 버튼 크기나 동작을 바꾸지 않는지 확인한다.
11. O15는 휴대폰의 라이트·다크, 세로·가로에서 서랍과 도구막대의 대비, 본문 여백과 화면 잘림을 확인한다. 라이브 프리뷰에서 가상 키보드를 열고 닫을 때 스크롤과 도구막대 위치가 정상인지 확인한다. 태블릿에서는 도구막대·서랍 색만 바뀌는지 확인한다.
12. OX01은 라이트·다크 화면에서 같은 노트를 PDF로 내보낸다. 긴 코드 줄과 긴 셀 텍스트가 잘리지 않는지, 여러 페이지에 걸친 표에 열 제목이 반복되는지, 화면에서는 기존 표시가 그대로인지 확인한다. 용지 설정은 동일하게 유지한다.
13. [검증 기록](10-obsidian-options.md#검증-기록)에 앱 버전·OS·모드·뷰·옵션 ID를 남긴다. 한 뷰에서 성공해도 다른 뷰를 통과 처리하지 않는다.
