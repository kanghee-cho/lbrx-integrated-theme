# 팔레트와 편집 경험

WGSN·Coloro의 2026년 색인 [Transformative Teal](https://www.adobe.com/express/learn/blog/color-of-year-trends)에서 **청록 방향만** 가져왔다. 아래 값은 공식 색상 복제가 아닌 자체 시안이다. 글 대부분은 중립색으로 두고, 청록은 링크·포커스·강조처럼 시선이 필요한 곳에 쓴다.

| 역할 / 팔레트 키 | 라이트 | 다크 | 용도 |
|---|---|---|---|
| 배경 / `paper` | `#F3F4EC` | `#19231F` | 옅은 종이색 / 녹색 기운의 차콜 |
| 본문 / `ink` | `#24362F` | `#DCE6DB` | 기본 배경 대비 각각 11.54:1, 12.59:1 |
| 보조 / `muted` | `#52655B` | `#A3B5A9` | 주석·인용. 읽어야 하는 내용은 흐리게 숨기지 않는다. |
| 주 강조 / `pine` | `#246958` | `#84C7AC` | 링크·포커스·문자열 |
| 슬레이트 블루 / `slate` | `#43617B` | `#97BBD6` | 함수·정보 |
| 자두 / `plum` | `#80516A` | `#D4A8BD` | 키워드 |
| 황토 / `ochre` | `#815919` | `#D6B378` | 숫자·경고 |
| 점토 / `clay` | `#A44540` | `#E59E91` | 오류·삭제 |

**읽기 기준:** [WCAG 대비 계산](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html)으로 본문/기본 배경은 프로젝트 목표 7:1, 보조 글자·링크·구문 및 선택된 글자/실제 배경은 4.5:1 이상을 요구한다. 포커스 표시는 인접색과 3:1 이상으로 설계한다. 링크 밑줄과 오류 기호도 사용해 색만으로 구분하지 않는다. ANSI 16색은 슬롯의 표준 의미를 유지하며 저대비 조합은 미리보기에서 경고한다. 외부 프로그램이 임의로 고른 모든 전경·배경 쌍의 가독성을 보장하지는 않는다.

**서체 시안:** 본문은 `LINE Seed Sans (EN) → LINE Seed Sans KR → LINE Seed JP_TTF → 시스템 sans-serif`, 16px / 1.65배, 코드는 `D2Coding ligature → 시스템 monospace`, 14px / 1.45배로 시작한다. 본문 목록은 앞의 글꼴이 지원하지 않는 문자를 다음 글꼴에서 찾는 순서이며, 문장 언어를 자동으로 판별해 전환하는 설정은 아니다. 테마는 글꼴 파일을 번들하거나 자동 설치하지 않는다. 목록을 지원하지 않는 앱에는 단일 글꼴과 대안 선택법을 안내한다. 이 값들이 피로를 줄인다고 단정하지 않고 한글 장문, 영문 코드, 숫자 `0O1l`, 혼합 줄바꿈을 실제 화면에서 비교해 조정한다.

**TUI 동선:** `lbrx-theme edit` → 모드 선택 → 팔레트 또는 역할 선택 → 견본 옆에서 RGB/HEX 조절 → 영향받는 역할과 대비 즉시 확인 → 명시적으로 저장. 원래 값과 편집 값을 나란히 표시하고 취소하면 원본을 유지한다. 색상만 나열하지 않고 같은 화면에 한글 문단·Markdown 링크·코드·선택 영역·ANSI 견본을 렌더링한다. 역할 이름과 HEX는 항상 표시한다.

True Color가 아닌 터미널에서는 근사색임을 표시하고, 대비 계산에는 원본 RGB를 사용한다. TUI 자체는 호스트 글꼴과 셀 높이를 바꿀 수 없다. 서체 입력 화면에서는 수치와 대상 앱 지원 여부를 보여주고 실제 조판 확인은 Typora 등 가져온 앱에서 한다.

## `edit` 화면 설계안: 공통 / 앱별 옵션

구분 기준은 **필수·선택 여부가 아니라 어디까지 바뀌는가**다. 공통 탭은 여러 출력이 참조하는 원본을, 앱별 탭은 한 앱의 적용 결과와 예외를 보여준다. 두 탭에 같은 값을 복사해 두지 않는다. 아래는 향후 TUI의 설계이며 현재 CLI 명령이나 TOML 키를 추가하지 않는다.

| 탭 | 항목을 어떻게 묶는가 | 편집 예 |
|---|---|---|
| **공통** | 색상(팔레트 → 역할), 서체(본문·코드), 문서 표현, 터미널 ANSI 16색. 항목마다 실제 소비하는 앱을 표시한다. ‘공통’이 모든 앱에서 지원된다는 뜻은 아니다. | `pine`의 HEX 변경과 `link`가 참조하는 팔레트 키 변경은 별도 작업이다. 전자는 `pine`을 쓰는 역할 전체에, 후자는 링크에만 영향을 준다. |
| **앱별 옵션** | 먼저 앱을 고른 뒤 **공통에서 가져온 값 / 이 앱 전용 / 앱에서 직접 설정**으로 나눈다. 기본 목록에는 지원 항목을, ‘미지원·예정 보기’에는 후보와 이유를 표시한다. | Typora의 링크색은 공통 역할로 이동한다. 다크 환경설정 왼쪽 메뉴(T13)와 라이트 오른쪽 패널(T14)은 Typora 전용으로, 현재는 색의 출처만 조회한다. |

```text
LBRX 편집  [공통]  앱별 옵션        색상 모드: 다크     미저장 1건
항목                     현재 값 / 변경안                 영향·검증
  색상 > 팔레트          원래: pine #84C7AC               적용: Typora
> 색상 > 역할 > 링크     변경: slate #97BBD6              링크 / 문서 배경 대비
  서체 > 본문            편집 대상: dark.roles.link       견본: [문서 링크]
  터미널 > ANSI          라이트 모드: 변경 없음           앱 화면: 미검증
Tab 영역 이동   Enter 편집   Esc 입력 취소   Ctrl+S 변경 검토
```

- 헤더에는 **편집 범위·모드·미저장 건수**를 항상 둔다. 색은 라이트/다크를 나눠 편집하되, 모드 공통인 본문 글꼴 순서를 편집할 때는 `양쪽 모드`로 표시한다. 좁은 터미널은 세 열 대신 `목록 → 상세 → 영향`으로 이동하고, 뒤로 가도 편집 위치와 초안을 유지한다.
- 각 항목에는 **유효값**(실제 출력에 쓰일 값), **출처**(원본 키 또는 고정 규칙), **영향 대상**을 표시한다. 예: `Windows Terminal > 코드 글꼴`에서는 전체 폴백 순서가 아니라 프로필에 출력할 단일 글꼴을 보여준다. 아이콘은 본문 폴백에 넣지 않는다. Typora의 기본 아이콘은 `앱 내장`이며, 보관 중인 아이콘 폰트가 있다고 해서 선택 가능한 옵션이 되는 것은 아니다.
- [전체 앱 공통 기준](11-cross-app-options.md)의 적용 범위를 UI에서도 구분한다. `원본`만 바로 편집하고 `고정`은 출처 조회, `후보`는 읽기 전용, `앱 설정`은 설정 위치 안내로 표시한다. D12처럼 한 항목 안에서도 **링크색은 편집 가능 / 밑줄은 고정**으로 행을 나눈다. `생성됨`과 `앱 검증됨`은 별도 표시한다. D 항목을 Typora에서 지원해도 Obsidian은 구현 전까지 `예정`이다.
- **앱별 재정의는 2단계 기능**이다. 첫 버전의 상속 행에서는 `공통 원본으로 이동`만 제공한다. 이후 스키마와 해당 어댑터가 지원하는 항목에만 `이 앱에서만 변경`을 연다. 재정의가 있으면 해당 앱·해당 모드에서 우선하며 `공통값으로 복귀`는 값을 복사하지 않고 예외를 제거한다. 공통값 변경 시 이미 재정의된 앱은 영향 대상에서 제외한다.
- **저장은 적용과 분리**한다. `Ctrl+S`에서 원본 키, 이전 값 → 새 값, 바뀌는 앱·모드를 검토하고 기존 `check` 기준을 통과한 경우에만 원본 TOML에 저장한다. 대비 실패 시 문제가 된 색 쌍과 비율을 표시하고 초안으로 돌아간다. 취소·종료 시 미저장 변경은 명시적으로 폐기하거나 계속 편집한다. 생성은 별도 `build`, 앱 적용은 수동이며 TUI가 설치된 글꼴이나 앱 설정을 변경하지 않는다.

## `edit` 설계: 언어 추가와 구문색 편집

**편집 단위는 언어별 색상표가 아니라 `앱이 식별한 토큰 → 언어의 토큰 의미 → 공통 역할 → 모드별 팔레트`다.** `공통 → 코드 구문 → 언어`에서 언어를 추가하거나 수정한다. `앱별 옵션 → 코드 구문`에서는 같은 데이터를 앱·뷰로 좁혀 본다. 두 화면에서 값을 복제하지 않는다.

```text
공통 › 코드 구문 › Go                      보기: 다크       초안
토큰 의미      유효 역할      색의 출처                샘플
키워드         keyword        공통                     func
함수 이름      function       공통 → dark → slate      PrintName
문자열         string         공통                     "hello"

[역할 연결 변경]   Go의 선택한 토큰만 변경
[공통 역할 편집]   function을 참조하는 다른 언어도 변경
[앱별 연결 보기]   앱이 이 토큰을 실제로 구별하는지 확인
```

### 추가·수정 동선

1. **언어 등록:** `언어 추가`에서 표시명 `Go`와 안정 ID `go`를 입력한다. 기본 의미(`comment`, `keyword`, `string`, `function`, `number`, `error`)는 **참조로 상속**한다. 아직 앱 연결이 없으면 `등록됨 · 출력 없음`이다. 등록은 문법이나 언어 서버 설치가 아니다.
2. **토큰 연결:** `토큰 의미 추가/수정`에서 예를 들어 `함수 이름 → function`을 선택한다. Go에서만 다른 역할을 쓰려면 **Go의 역할 연결 변경**을 고른다. HEX를 언어에 복사하지 않는다. 공통 팔레트에 없는 새 색이 정말 필요하면 색 역할을 새로 만들고 라이트·다크 팔레트 키를 각각 지정한 뒤 그 역할에 연결한다.
3. **색 변경:** `공통 역할 편집`은 선택한 모드의 역할 참조를 바꾼다. 예를 들어 `dark.roles.function`을 바꾸면 이를 쓰는 모든 언어의 다크 함수색만 달라진다. **팔레트 HEX 편집**은 그 팔레트 키를 참조하는 다른 역할까지 바꾸므로 별도 동작으로 표시한다.
4. **앱 연결:** 앱·뷰와 해당 앱의 언어 ID를 선택한 뒤, 어댑터가 지원하는 토큰 식별자를 추가하거나 수정한다. 예를 들어 VS Code의 `powershell`과 Vim의 `ps1`은 같은 언어에 연결할 서로 다른 ID다. [VS Code](22-vscode-language-highlighting.md)는 TextMate와 semantic token을, [Vim](23-vim-language-highlighting.md)은 관측한 구문 그룹과 최종 그룹을, [Obsidian](24-obsidian-language-highlighting.md)은 읽기·라이브 프리뷰의 언어/토큰 식별 가능 여부를 구분한다. 앱이 함수 호출과 변수를 구별하지 못하면 `식별 불가`로 표시한다. 이때 모든 변수를 함수색으로 바꾸는 예외는 제공하지 않는다.

### 저장 계약과 상속

| 원본에 보관할 사용자 선택 | 해석 규칙 |
|---|---|
| 언어 ID·표시명, 기본값과 다른 `토큰 의미 → 역할` | 기본 연결은 저장하지 않는다. 언어별 연결은 두 모드에 공통이며 실제 색은 해당 모드의 역할에서 구한다. |
| 선택적 앱·뷰별 언어 ID와 토큰 연결 | 지원되는 가장 좁은 범위의 명시적 선택 → 언어별 연결 → 공통 기본 순서. `상속으로 복귀`는 예외만 제거한다. `앱에 맡김`은 해당 범위의 명시적 규칙을 생략하며, 앱에서 상속된 색까지 없애지는 않는다. |
| 역할 키와 라이트·다크 팔레트 참조 | 색은 기존 모드별 원본에만 둔다. 참조 중인 역할 삭제는 사용처를 보여주고 차단한다. 언어 삭제는 그 언어의 연결만 제거하며 공유 역할과 다른 언어는 남긴다. |

어댑터의 지원 범위, 내장 기본 매핑, 토큰을 출력 문법으로 변환하는 규칙은 [기존 옵션 계약](04-option-strategy.md)에 따라 코드에서 관리한다. 사용자는 지원되는 종류의 식별자와 역할만 편집한다. CSS·Vim 명령 같은 실행 가능한 원문을 입력받지 않는다. **현재 스키마에는 언어 테이블이 없다.** 구현 시 선택적 저장 구조를 정하고, 언어 설정이 없는 기존 TOML은 수정 없이 같은 출력을 내도록 한다. 지원하지 않는 앱·뷰는 편집 불가로 표시한다.

### 저장 전 확인과 완료 기준

- `Ctrl+S` 검토 화면에 변경 전후 역할·최종 HEX, 영향받는 언어·앱·뷰·모드와 제외 이유를 표시한다. 코드 샘플은 **역할 견본**이지 실제 앱의 토큰 인식 결과가 아니다. `출력 가능`, `생성됨`, `앱에서 확인됨`을 구분한다.
- 중복 언어 ID, 같은 범위의 충돌 연결, 없는 역할·팔레트 참조, 빈 식별자, 지원하지 않는 예외는 필드별 오류로 표시한다. 새 구문색도 양쪽 모드의 적용할 코드 배경에서 대비 4.5:1을 검사한다. 오류나 취소 시 원본·생성물을 바꾸지 않는다. 저장 후 생성은 별도 `build`다.
- 승인 시에는 **Go 추가 전후 기존 언어 출력 동일**, **Go 예외 변경 시 다른 언어 불변**, **공통 다크 역할 변경 시 참조하는 다크 출력만 변경**, **예외 제거 시 상속 복원**, **저장 후 재진입 시 같은 연결 복원**을 각각 확인한다.
