# Typora 테마 옵션 체크리스트

**현재 상태:** 라이트·다크 CSS 생성은 구현됐다. 본문·코드 서체, 주요 문서 색상, 코드 블록 구문색은 출력되지만, Typora에서 두 모드를 직접 비교한 검증 기록은 아직 없다. 표·작업 목록·집중 모드·인쇄 전용 스타일은 구현되지 않았다.

이 목록의 범위는 **LBRX가 표현할 디자인 선택**, 그리고 테마만으로 구현할 수 없어서 **Typora 설정으로 남겨야 할 항목**이다. 임의의 CSS 속성 전체나 Typora의 모든 환경설정 목록은 아니다. 새 후보를 발견하면 아래 분류에 ID를 추가한다.

### 체크 기준

- `[x]`는 **LBRX가 해당 결과를 생성한다**는 뜻이다. Typora 기본 테마에서 이미 보이는 효과, 설계 문서에만 있는 옵션, 브라우저의 기본 동작은 체크하지 않는다.
- **원본** = [테마 TOML](../themes/lbrx.toml)에서 바꿀 수 있다. **고정** = CSS는 생성하지만 사용자가 조정하는 TOML 키는 없다. **후보** = 미구현이며 이름이나 단위가 확정된 설정이 아니다.
- `D`는 Obsidian과 **의미를 공유할 후보**, `T`는 **Typora 전용 매핑**, `X`는 **내보내기·앱 설정**이다. `D`를 체크해도 Obsidian 구현은 완료되지 않는다.
- 실제 앱 검증은 맨 아래 **검증 기록**에 별도로 남긴다. 일부만 동작하면 항목을 나눠 완료된 부분만 체크한다.

## 1. 문서 공통 후보 — Obsidian에서 같은 ID로 검토

### 색·서체·조판

- [x] **D01 문서 배경·본문색** — 원본 `background`, `text`. 두 모드에서 본문과 작성 영역 배경을 비교한다.
- [x] **D02 본문 글꼴 우선순위** — 원본 `typography.prose.families`. EN → KR → JP → 시스템 대체 순서를 보존한다.
- [x] **D03 본문 크기·줄 높이** — 원본 `typography.prose.size_px`, `line_height`. 한 줄 내부 간격과 문단 사이 간격을 혼동하지 않는다.
- [x] **D04 코드 글꼴·크기·줄 높이** — 원본 `typography.mono`. 인라인 코드와 코드 블록 모두에 적용한다.
- [ ] **D05 본문 최대 폭·좌우 여백** — 후보. 넓은 창에서 행 길이를 제한하되 좁은 창에서 가로 스크롤을 만들지 않는다.
- [ ] **D06 문단 앞뒤 간격** — 후보. 연속 문단의 여백만 바꾸고 빈 줄이나 커서 위치를 추가하지 않는다.
- [ ] **D07 문단 정렬·쓰기 방향** — 후보. 양쪽 정렬, RTL, 세로쓰기는 별도 선택이며 혼합 문장의 편집 가능 여부를 확인한다.
- [ ] **D08 서체 세부 표현** — 후보. 자간, 합자, 작은 대문자, 제목 대문자 변환. 대소문자 변환이 원문 변경처럼 보이지 않는지 확인한다.

### 제목·링크·인용·강조

- [x] **D09 제목색** — 원본 `heading`을 H1–H6에 연결한다.
- [ ] **D10 제목 단계별 조판** — 후보. H1–H6의 크기·굵기·위아래 간격·구분선을 각각 구별한다.
- [ ] **D11 제목 자동 번호** — 후보. CSS로 표시한 번호는 Markdown 원문에 저장되지 않는다. 목차·개요의 번호는 별도 항목이다.
- [x] **D12 링크색·밑줄** — 색은 원본 `link`, 밑줄은 고정. 밑줄을 끄는 옵션은 없다.
- [x] **D13 키보드 링크 포커스** — 색은 원본 `focus`, 윤곽선 굵기·거리는 고정. 편집기의 집중 모드와 다르다.
- [x] **D14 인용문** — 색은 원본 `quote`, 시작 방향 테두리·안쪽 여백은 고정.
- [x] **D15 인라인 코드색** — 원본 `inline_code`. 별도 배경색이나 테두리 옵션은 없다.
- [x] **D16 일반 텍스트 선택색** — 원본 `selection_text`, `selection_background`. 편집 엔진이 별도로 그리는 선택 영역은 T05에서 확인한다.
- [ ] **D17 본문 강조 표현** — 후보. 굵게·기울임·취소선·하이라이트를 본문색과 구별한다.
- [ ] **D18 각주·참조·수평 구분선** — 후보. 각주 표식, 각주 본문, 구분선을 일반 링크·문단과 구별한다.

### 코드·표·목록·이미지

- [x] **D19 코드 블록 바탕·테두리** — 본문 `background`, `text`, `muted`를 사용한다. 모서리·안쪽 여백은 고정이다. 독립 코드 배경 토큰은 없다.
- [x] **D20 코드 구문색** — 원본 `comment`, `keyword`, `string`, `function`, `number`, `error`. Typora는 `.cm-s-inner`에 연결하지만 Obsidian은 해당 앱의 렌더러에 따로 연결해야 한다.
- [ ] **D21 표** — 후보. 헤더 강조, 행·열 구분선, 셀 여백, 교대 행, 넓은 표의 넘침을 다룬다. 표 편집 도구의 동작은 대상이 아니다.
- [ ] **D22 순서·비순서 목록** — 후보. 표식, 중첩 들여쓰기, 항목 사이 간격. 번호 자체는 문서 내용으로 유지한다.
- [ ] **D23 작업 목록** — 후보. 체크 상자, 미완료·완료색, 완료 취소선. 완료 항목이나 그 아래 미완료 항목을 숨기지 않는다.
- [ ] **D24 이미지·캡션** — 후보. 최대 너비, 정렬, 캡션 간격·색. 원본 이미지 크기·저장 위치는 바꾸지 않는다.
- [ ] **D25 수식** — 후보. 인라인/블록 수식의 주변 간격, 배경, 넘침. 수학 기호의 전용 글꼴은 본문 글꼴로 일괄 덮지 않는다.
- [ ] **D26 알림·콜아웃** — 후보. 유형별 표식·강조선·라벨. Typora 알림과 Obsidian 콜아웃의 문법·중첩 의미가 같다고 전제하지 않는다.

## 2. Typora 편집기·탐색·도식

- [x] **T01 테마 패키지** — 고정. `lbrx-light.css`, `lbrx-dark.css`, 적용 안내를 생성한다. 앱에 복사하거나 모드를 자동 전환하지 않는다.
- [ ] **T02 집중 모드** — 후보. `--blur-text-color`로 비활성 문단색을 조정하고 활성 문단·링크 가독성을 확인한다. 모드를 켜는 명령은 생성하지 않는다.
- [ ] **T03 라이브 편집 기호** — 후보. 커서가 들어간 강조·링크의 Markdown 기호, 표시 텍스트, URL을 구별한다. 항상 보이기/숨기기는 별도 선택이다.
- [x] **T04 코드 편집기 줄 번호·커서 색** — `muted`, `focus`를 매핑한다. 줄 번호 표시 여부는 변경하지 않는다.
- [ ] **T05 코드 편집 상태** — 후보. CodeMirror 선택 영역, 활성 줄, 괄호 짝 강조. D16의 `::selection` 출력만으로 완료 처리하지 않는다.
- [ ] **T06 Markdown 소스 모드** — 후보. 편집 본문과 별도로 글꼴·배경·구문·선택을 확인한다. 코드 펜스용 `.cm-s-inner`는 소스 모드 전체의 구현이 아니다.
- [ ] **T07 문서 내부 `[TOC]`** — 후보. 단계별 들여쓰기·간격·링크·표시 깊이·자동 번호. 본문 제목이나 사이드바 개요를 함께 숨기지 않는다.
- [ ] **T08 사이드바 개요·파일 트리** — 후보, 현재 문서 영역 범위 밖. 활성 항목·계층 표시·개요 번호를 구분한다. 접힘 상태나 파일 순서는 앱에 맡긴다.
- [ ] **T09 YAML 머리말·편집 보조 UI** — 후보, 버전별 선택자 확인 필요. 메타데이터 블록, 검색 결과 강조, 링크 편집 팝업을 본문과 구분한다.
- [ ] **T10 Mermaid 배색·정렬** — 후보. 라이트 `neutral`/다크 `dark`를 시작점으로 노드·연결선·레이블을 확인한다. 문서 내 개별 Mermaid 설정과 충돌하는지 검사한다.
- [ ] **T11 Mermaid 도식별 표현** — 후보. 시퀀스 번호, 흐름도 곡선, 간트 좌측 여백. 번호는 의미를 바꿀 수 있어 기본 강제하지 않는다.
- [ ] **T12 기타 다이어그램** — 후보. `sequence`의 `simple`/`hand`와 `flow` 미리보기를 Mermaid와 별도로 검증한다.
- [x] **T13 다크 환경설정 왼쪽 메뉴 대비** — 메뉴 배경·글자 및 선택·마우스 오버·포커스 색을 생성한다. 문서 탐색 사이드바(T08)와는 별개이며, 실제 앱 화면 검증은 아직 남아 있다.
- [x] **T14 라이트 환경설정 오른쪽 내용 대비** — 오른쪽 패널에 밝은 배경과 어두운 본문·안내문 색을 짝지어 적용하고, 브라우저 기본 입력 컨트롤에는 라이트 색상 체계를 요청한다. 왼쪽 메뉴에는 적용하지 않는다. 실제 앱 화면 검증은 아직 남아 있다.

## 3. 출력 매체와 테마 밖의 설정

| ID | 옵션 | LBRX 구현 상태·경계 |
|---|---|---|
| X01 | 인쇄·PDF용 밝은 종이색, 텍스트·링크색 | 미구현. 편집 테마와 분리된 인쇄 규칙 또는 내보내기용 테마 후보. |
| X02 | 페이지 나눔, 제목 고립 방지, 표·그림 분할 | 미구현. 두 페이지 이상인 PDF로 실제 확인해야 한다. |
| X03 | HTML 내보내기 테마·목차, 그림 내보내기 폭·글꼴 크기 | 미검증. Typora 내보내기 프로필에서 선택하는 값과 CSS 효과를 분리한다. |
| X04 | PDF 용지 크기·머리말·꼬리말·메타데이터 | 앱 설정. 현재 생성기가 수정하지 않는다. 다크 편집 → 라이트 PDF는 별도 검증한다. |
| X05 | EPUB CSS·표지, DOCX 참조 문서, LaTeX/Pandoc 템플릿 | 별도 배포 형식. 현재 Typora CSS의 지원 대상으로 계산하지 않는다. |
| X06 | 집중·타자기 모드 활성화, 다이어그램 활성화, 단축키, 이미지 저장·업로드 | 앱 동작. 테마가 자동으로 변경하지 않는다. |

## 4. 구현 증거와 검증 기록

| 확인 단계 | 현재 근거 | 체크를 갱신하는 기준 |
|---|---|---|
| 원본에서 조정 가능 | [테마 TOML](../themes/lbrx.toml), [Typora 변환 코드](../src/typora.rs) | 파서가 받는 값이 실제 CSS 선언에 연결된 경우만 **원본**으로 적는다. |
| CSS 생성 | [문서 스타일](../src/typora.css), [다크 환경설정 스타일](../src/typora-preferences-dark.css), [빌드 테스트](../src/build.rs) | 해당 ID의 선언·선택자를 확인한다. 두 모드의 생성, 서체 순서, 다크 링크 변경 격리는 테스트 대상이다. 모든 시각 항목을 자동 검증한 것은 아니다. |
| 실제 앱 확인 | **기록 없음** | [적용 방법](07-typora.md)에 따라 아래 표에 ID별 PASS/FAIL과 앱 버전을 남긴다. 실패한 뷰만 명시하고 생성 체크와 혼동하지 않는다. |

| 날짜 | OS / 앱 버전 | ID | 뷰·모드 | 결과와 차이 |
|---|---|---|---|---|
| — | Typora 미확인 | — | 라이트·다크 | 아직 기록 없음 |

## 5. Obsidian에 연결할 때

**아직 Obsidian 구현은 없다.** D01–D26은 같은 ID로 추적하되 Typora 체크를 복사하지 않는다. 아래 표는 착수 시 나눌 검증 범위다. 한 그룹의 일부만 구현하면 그 ID만 별도 행으로 분리한다.

| 공유 후보 | Obsidian 읽기 뷰 | Obsidian 라이브 프리뷰 | 가장 먼저 확인할 차이 |
|---|---|---|---|
| D01–D08 색·서체·조판 | 미착수 | 미착수 | 사용자 글꼴 설정을 덮어쓰는지, 문단 간격이 편집 빈 줄까지 늘리는지 |
| D09–D18 제목·링크·인용·강조 | 미착수 | 미착수 | 제목 번호의 중복, 내부 링크와 외부 링크, 커서가 있는 링크의 구문 표시 |
| D19–D20 코드 | 미착수 | 미착수 | 렌더링된 코드와 편집 중인 코드가 서로 다른 구문 클래스를 쓰는지 |
| D21–D26 표·목록·이미지·수식·알림 | 미착수 | 미착수 | 중첩 체크리스트, 표 편집, 접힌 콜아웃이 원래 동작을 유지하는지 |

두 앱에서 **의도·단위·적용 범위·샘플 결과**가 일치할 때만 [공통 옵션으로 승격](04-option-strategy.md)한다. 예를 들어 본문 최대 폭(D05)은 공유 후보지만, Typora의 `.md-meta`나 `--mermaid-theme`를 공통 원본 키로 만들지는 않는다. T·X 항목의 유사 기능이 발견되면 기존 ID를 참조해 차이를 기록하고, 일치가 확인되기 전까지는 별도 매핑으로 둔다.
