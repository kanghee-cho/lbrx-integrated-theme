# 원본과 생성 구조

```text
themes\lbrx.toml                 유일한 디자인 원본 (버전 관리)
    ↓ 읽기 / 명시적 저장
Rust CLI ─ edit (TUI) / check / build
    ↓ 두 모드의 참조 해석 → 타입·대비 검사 → 앱별 변환
dist\lbrx\<target>\              가져올 파일, 옵션 설정 예시, 설치 안내
```

**변경 단위는 세 층이다.** 팔레트는 실제 색, 역할은 색의 용도, 어댑터는 앱에서의 표현을 정의한다. 예를 들어 강조색 전체를 바꾸려면 `pine`만 수정한다. 링크만 파랗게 하려면 `link`의 참조를 `slate`로 바꾼다. CSS 선택자나 Vim 하이라이트 그룹은 원본에 넣지 않는다.

```toml
# 원본의 일부. dark에도 같은 키 집합이 필요하다.
schema_version = 1
[light.palette]
paper = "#F3F4EC"
ink = "#24362F"
pine = "#246958"
slate = "#43617B"

[light.roles]
background = "paper"
text = "ink"
accent = "pine"
link = "pine"
```

| 토큰 집합 | 계약 |
|---|---|
| 모드별 팔레트 | 불투명 sRGB `#RRGGBB`. 역할은 같은 모드의 팔레트 키만 참조한다. |
| 모드별 역할 | UI(본문·표면·선택·포커스), 문서(제목·링크·인용·인라인 코드), 구문(주석·문자열·키워드·함수·숫자), 상태(오류·경고·성공), 터미널(전경·배경·커서). 같은 색을 써도 의미가 다르면 키를 분리한다. |
| ANSI 슬롯 | `[light.ansi]`와 `[dark.ansi]`에 키 `0`부터 `15`까지 모두 두고, 각 값은 같은 모드의 팔레트 키를 참조한다. |
| 공통 서체 | `[typography.prose]`와 `[typography.mono]`에 우선순위 있는 글꼴 목록 `families`, 기준 크기 `size_px`(CSS px), 줄 높이 `line_height`(배수)를 둔다. 목록은 비어 있지 않아야 하며 수치는 유한한 양수여야 한다. 앱 단위 변환은 어댑터 책임이다. |

**Rust 구성 제안:** 초기에는 단일 Cargo 패키지로 시작한다. `model`은 `serde`/`toml`로 읽고 `resolve`는 두 모드를 검증해 완전한 값으로 만든다. `tui`(Ratatui/Crossterm)와 `build`는 같은 모델·검사를 호출한다. 각 `targets` 모듈은 해석된 값과 지원표를 받아 파일을 반환한다. 새 앱은 어댑터와 출력 검사를 추가하며, 기존 테마에 그 앱 전용 HEX를 복제하지 않는다.

**실패와 재생성:** `check`는 원본을 변경하지 않는다. 스키마 버전 불일치, 누락된 역할·ANSI 슬롯, 알 수 없는 참조, 잘못된 크기나 필수 대비 미달은 모드·키·원인을 표시한다. `build`는 모든 대상을 임시 출력에 생성·검사한 뒤에만 기존 생성본을 교체한다. 실패 시 직전 생성본을 보존한다. 같은 원본과 도구 버전에서는 같은 테마 값과 파일 구성이 나와야 한다. `dist` 수동 편집은 다음 생성에서 사라지므로 변경은 원본에 한다.

## 현재 구현: 생성 기반과 Windows Terminal

현재 `build`는 `resolve`의 검증을 통과한 역할과 ANSI 참조를 실제 HEX로 해석해 `dist\lbrx\resolved.toml`을 만든다. 역할 키는 정렬하고 ANSI는 슬롯 0–15 순서의 배열로 저장한다. 생성 시각·임시 경로를 출력에 넣지 않으며 같은 원본·도구 버전의 출력은 바이트 단위로 같다. Windows Terminal 어댑터는 같은 해석 결과에서 배색표와 별도 글꼴 조각을 만든다. 원본과 앱 설정은 변경하지 않는다.

**게시 절차**

1. 원본 검증·해석·직렬화를 먼저 수행한다. 잘못된 원본은 출력 폴더를 만들거나 변경하지 않는다.
2. `dist\.lbrx-build.lock`을 배타적으로 생성해 동시 빌드를 거부한다. `dist\.lbrx-build`에 임시 파일을 쓰고 원래 생성 내용과 일치하는지 확인한다. TOML과 JSON은 다시 파싱한다.
3. 기존 `dist\lbrx`가 있으면 생성물 형식의 `resolved.toml`과 허용된 Windows Terminal 산출물만 있는 실제 디렉터리인지 검사한다. Windows Terminal 폴더가 없는 이전 출력도 교체할 수 있다. 알 수 없는 파일·하위 폴더·링크는 삭제하지 않고 교체를 거부한다.
4. 기존 출력을 `dist\.lbrx-previous`로 옮긴 뒤 임시 출력을 `dist\lbrx`로 옮긴다. 두 번째 이동 실패 시 기존 출력을 원래 위치로 복구한다. 복구도 실패하면 보존된 백업 경로를 오류로 알린다.
5. 성공 후 이전 백업을 정리한다. 임시 출력·잠금 정리 실패도 오류로 알리며, 새 출력 게시 후 백업 정리만 실패한 경우에는 그 상태를 명시한다.

이 방식은 일반적인 오류에 대한 롤백이며 **프로세스 강제 종료·정전까지 보장하는 단일 원자적 디렉터리 교체는 아니다.** 두 번의 이동 사이에는 출력 경로가 잠시 없을 수 있다. 작업 중단 흔적이 있으면 자동 삭제·재시도하지 않는다. 실행 중인 빌드가 없는지 확인한 뒤, `.lbrx-previous`가 있고 `lbrx`가 없으면 백업을 `lbrx`로 복원한다. 두 폴더가 모두 있으면 내용을 확인해 어느 쪽을 보존할지 판단한다. 필요한 내용을 보관한 후 남은 임시 디렉터리·백업·잠금을 수동 정리하고 다시 실행한다.
